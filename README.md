# 聊成文章 · chat-to-essay

当前版本：**0.1**。

一个通过聊天帮助你写个人感悟的 Skill。先聊喜欢或在意的游戏、电影、动漫剧集、书籍等，再把你的想法整理成适合个人博客的文章。

你不需要会写文章，也不需要提前准备提纲。一句“这个结局让我很难受”就可以开始。

## 它怎么工作

- **先闲聊。** 从你愿意说的内容开始，顺着具体的感受和片段展开，不发写作问卷。
- **一起把想法聊深。** 追问感受背后的原因、判断的变化和重要区别，不直接替你解释为什么感动，也不需要你反复提醒 AI 继续提问。
- **有自己的看法。** AI 可以提出有依据的不同理解，再听你回应和反驳；不会为了制造冲突而反驳，也不会把未获认同的解释冒充成你的观点。
- **主动补足相关资料。** 讨论复杂剧情和人物关系前先核实背景，尽量不让你承担科普工作；资料少或无法确认时会说明具体缺口，并注意避免剧透。
- **观点展开了再写。** 不按聊天轮数、人物数量或剧情复述量判断质量。过早要求成稿时，会说明还缺哪些理由或联系，让你选择继续聊或先写短版。
- **文章有取舍、有推进。** 根据你的核心看法选择材料，让经历、理由、区别与认识变化形成联系，不把所有聊过的人物依次排列。交付前检查并修订缺少展开的流水账。
- **忠于你的表达。** 默认生成第一人称 Markdown 博客随笔，保留你的立场、语气和仍未想明白的问题，不编造经历、不强行升华。

文章既可以谈整部作品，也可以只谈一个角色、一段情节或一个游戏机制，前提是有足够的个人表达可以展开。

这里的深度，是让读者看懂你为什么这样想，以及哪些细节改变或丰富了你的判断。它可以完全停留在作品和个人体验内部，不需要引出人生大道理。

## 安装到 Codex

将本目录作为 `chat-to-essay` 文件夹，放入 `$CODEX_HOME/skills/`；未设置 `CODEX_HOME` 时使用 `~/.codex/skills/`。

目录结构：

```text
chat-to-essay/
├── SKILL.md
├── agents/
│   └── openai.yaml
├── references/
│   └── writing-guide.md
└── README.md
```

`SKILL.md` 是核心指令，`references/writing-guide.md` 提供写作阶段的编辑与质量检查方法，`agents/openai.yaml` 提供 Codex 中的展示名称和起始提示。安装时保留完整目录。该 Skill 不包含脚本，也不绑定特定检索服务；作品查询由使用环境提供的检索能力完成。无可用检索能力时，会明确告知并围绕你提供的信息继续聊天。

## 开始使用

例如：

> 使用 $chat-to-essay，陪我聊聊刚玩完的一个游戏。我很喜欢它，但说不清楚为什么，想最后写成博客文章。

也可以从一个具体困惑开始：

> 使用 $chat-to-essay，我想聊聊最近看的一部动画。我觉得主角最后的选择不太对，但朋友都很喜欢这个结局。

聊到想整理时，直接说“帮我写出来”。如果生成的段落不像你，可以指出“我不是这个意思”或“这里写得太重了”，继续调整。

默认文章在对话中以 Markdown 交付；需要文件时，可以要求保存为 `.md`。Skill 本身可作为 GitHub 仓库内容分享，文章用于你的个人博客；使用 Skill 不会自动发布文章或推送仓库。
